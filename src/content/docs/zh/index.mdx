# NextDevTpl 文档

NextDevTpl 4.0.0 在生成时选择一套皮肤，并根据运行模式生成独立应用。完整模式保留所选的认证、支付、积分、存储、邮件、任务和部署能力；演示模式保留同一套产品视图，以本地样例数据展示界面操作。

## 先选择运行模式

| 模式 | 适合场景 | 生成结果 |
| --- | --- | --- |
| `full`（默认） | 构建真实产品 | 按预设或自定义选择保留产品模块、服务适配器、环境变量、数据库 Schema 和部署文件 |
| `demo` | 展示或评估前端 | 固定保留 17 条用户路由、20 个皮肤视图；只生成 `server` 项目，不含业务 API、数据库、认证或支付服务 |

演示模式中的登录、资料、套餐与工单动作只更新当前标签页内存。站内软导航和切换语言会保留改动；刷新或新开标签页后恢复默认样例。业务资料不写入 `localStorage` 或 Cookie。

演示导出的生成记录关键字段如下；实际文件还包含 catalog 和皮肤来源记录：

```json
{
  "mode": "demo",
  "preset": "custom",
  "target": "server",
  "modules": [],
  "adapters": {},
  "bindings": [],
  "viewModules": ["auth", "blog", "dashboard", "marketing", "pseo", "settings", "shared", "support"],
  "demo": { "dataSha256": "..." }
}
```

## 皮肤在生成时选定

默认皮肤可直接使用，也可通过 `--skin` 指定本地皮肤目录或远端 HTTPS 归档。远端来源必须提供归档 SHA-256；可选的访问令牌只从命令执行环境读取，不保存在生成记录中。皮肤结构、视图编号、资源授权及检查要求见[皮肤制作指南](/zh/docs/skin-authoring)。

`--palette` 只适用于内置默认皮肤。生成器随包提供 149 套 StyleKit 离线配色快照，选中后会把对应 MIT 署名写入生成项目。

## 两种使用方式

产品项目使用 `create-nextdevtpl` 生成独立源码。完整仓库用于维护模板、官方皮肤、模块和生成器；仓库实现细节请参考公开仓库中的对应模块文档。
