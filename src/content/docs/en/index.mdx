# NextDevTpl Documentation

NextDevTpl 4.0.0 selects one skin at generation time and produces an independent app for the chosen runtime mode. Full mode keeps the selected authentication, payment, credits, storage, mail, jobs, and deployment capabilities. Demo mode keeps the same product views and uses local sample data for interface interactions.

## Choose a Runtime Mode

| Mode | Use it for | Generated result |
| --- | --- | --- |
| `full` (default) | Building a real product | Keeps product modules, service adapters, environment variables, database schema, and deployment files selected by a preset or custom configuration |
| `demo` | Showing or evaluating the frontend | Keeps 17 user-facing routes and 20 skin views; generates a `server` project without business APIs, a database, auth, or payment services |

Sign-in, profile, plan, and ticket actions in demo mode update only the current tab's in-memory data. Soft navigation and locale changes preserve those updates; refreshing or opening a new tab restores the default sample. Business data is not written to `localStorage` or cookies.

The following excerpt shows the demo record's key fields; the actual file also contains catalog and skin source records:

```json
{
  "mode": "demo",
  "preset": "custom",
  "target": "server",
  "modules": [],
  "adapters": {},
  "bindings": [],
  "viewModules": ["auth", "blog", "dashboard", "marketing", "pseo", "settings", "shared", "support"],
  "demo": { "dataSha256": "..." }
}
```

## Skins Are Selected During Generation

Use the built-in default skin, a local skin directory, or a remote HTTPS archive with `--skin`. Remote sources require an archive SHA-256 digest. Optional access tokens are read from the command environment and are not recorded in the generated manifest. See the [skin authoring guide](/en/docs/skin-authoring) for package structure, view IDs, asset licenses, and validation rules.

`--palette` is available only for the built-in default skin. The package includes an offline snapshot of 149 StyleKit themes. Selecting one adds its MIT attribution to the generated app.

## Two Ways to Use the Project

Use `create-nextdevtpl` to generate independently maintained product source. The full repository is for maintaining the template, official skins, modules, and generator; repository implementation details are documented in the corresponding public module guides.
