> 当前稳定基线：`v2.6.0`
>
> 当前阶段：M0 运营观测基线（未开始）
>
> 上一代路线图：[NextDevTpl 2.x 路线图](roadmap2.x.md)

> 最近更新时间：2026-08-01

## 项目目标

NextDevTpl 3.x 要让独立 SaaS 从上线第一天起就能回答五个问题：用户从哪里来、
在哪一步流失、是否获得核心价值、是否愿意付费，以及每个用户是否赚钱。

3.x 在 2.x 模块化和适配器体系上增加一套可裁剪的运营观测能力。生成项目可以
预置埋点、漏斗、留存、收入、成本、稳定性和告警，同时继续保留全部源码，不依赖
NextDevTpl 线上服务。

## 核心原则

1. **先回答经营问题**：只采集能支持决策的数据，禁止默认记录所有点击。
2. **数据来源明确**：行为与归因来自产品分析；收入、订阅和积分以业务数据库及
   支付 Webhook 为准；错误与性能来自日志和监控。
3. **事件契约稳定**：事件名称、版本和属性使用严格类型与运行时校验，模块只能
   发布自己登记的事件。
4. **隐私默认收紧**：禁止采集密钥、Cookie、Authorization、邮箱、完整提示词、
   上传内容等敏感数据；浏览器分析遵守用户同意状态。
5. **运营不阻塞业务**：分析服务异常不得让注册、支付、积分或核心功能失败。
6. **适配器按需生成**：未选择的分析与告警供应商源码、依赖和环境变量不得进入
   最终项目。
7. **指标口径可复验**：每个指标说明来源、公式、时间范围、时区和缺失状态，
   配置完成不能代替真实数据验证。

<a id="m0"></a>
## M0 - v3.0 运营观测基线与埋点内核

建立供应商无关的 `telemetryService`，统一客户端和服务端的事件信封、身份上下文、
事件版本、属性校验与失败降级。首批计划提供 `noop`、结构化日志和 PostHog
适配器，并把现有 Google Analytics 接入迁入同一选择体系。

M0 同时冻结核心指标名称和数据来源。当前 `logEvent()` 只约束事件名，属性仍是
任意对象；3.x 要把事件属性也纳入严格类型和运行时校验。

<a id="m1"></a>
## M1 - v3.1 标准运营事件与来源归因

在认证、营销、Dashboard、支付、订阅、积分、支持、后台任务和 API/Action
边界接入标准事件。模板自动记录通用链路，同时为具体产品保留
`first_value.completed` 和 `core_action.completed` 两个明确接入点。

首次来源、最近来源、UTM、匿名 ID、会话 ID、登录用户 ID、版本与部署环境使用
统一上下文。用户注册或登录后可以连接此前的匿名访问，但不把邮箱等个人信息发送
给分析供应商。

<a id="m2"></a>
## M2 - v3.2 运营驾驶舱与指标聚合

新增可选 `operations` 模块，为管理员提供总览、漏斗、留存、产品使用和系统健康
视图。行为指标通过产品分析适配器读取；用户、积分、工单等业务指标直接从数据库
聚合；高成本查询写入按日快照。

驾驶舱必须区分 `zero-data`、`not-configured`、`unauthorized`、`query-failed` 和
`partial`，禁止把接入配置或陈旧快照展示成当前有效数据。

<a id="m3"></a>
## M3 - v3.3 收入与订阅健康

从支付 Webhook、订阅状态和价格配置生成可审计的收入读模型，覆盖新增付费、MRR、
付费转化、续费、流失、退款和支付失败。浏览器端 `checkout.completed` 只用于分析
用户路径，不作为收入确认依据。

金额统一保存货币和最小货币单位；月付与年付使用明确规则折算 MRR。指标页面显示
统计时区、更新时间和数据完整性，避免把估算值包装成会计结果。

<a id="m4"></a>
## M4 - v3.4 AI 成本与毛利

扩展 AI 服务契约，返回模型、供应商、输入/输出 Token、总 Token、耗时和供应商
可提供的用量信息。价格表按生效时间版本化，不能取得真实 Token 时明确标记
`unavailable` 或 `estimated`。

运营页按模型、功能、用户和日期聚合请求量、成功率、延迟、积分收入、估算成本与
毛利。任何提示词、模型原始回复和上传内容都不进入运营事件。

<a id="m5"></a>
## M5 - v3.5 运营告警与自动化

为支付失败、Webhook/任务失败、错误率、AI 成本突增、余额异常和转化下降提供规则
与通知。首批通知适配器计划为 `noop`、邮件和通用 Webhook，通用 Webhook 可连接
飞书、Slack 或 Discord 等工具。

规则执行具备幂等键、冷却期、恢复通知和发送历史。3.x 只做观察与通知，不自动
退款、封禁用户、修改套餐或关闭服务。

<a id="m6"></a>
## M6 - v3.6 运营适配器兼容与稳定版

补充 Umami 等轻量分析适配器，建立能力声明，明确漏斗、留存、身份关联和服务端
事件等差异。GA4 保留获客与广告归因定位，不要求它承担全部产品分析能力。

验证矩阵覆盖 Server、Docker Compose、Vercel 和 Cloudflare Workers，检查未选
适配器被完整删除、环境变量正确裁剪、同意状态生效，并对支持的官方服务执行真实
写入与只读查询冒烟验证。

<a id="m7"></a>
## M7 - 3.x 用户文档与发布收尾

同步 README、生成器参数、环境变量、内置中英文 `/docs`、隐私说明、指标字典、
供应商配置、运营驾驶舱、告警和故障排查。所有页面只描述已经实现并验证的能力。

发布前重新生成官方预设，完成格式化、lint、严格类型检查、测试、生产构建、发布
包检查和真实部署验证，并记录最终兼容矩阵与已知限制。

## 标准经营漏斗

```text
landing.viewed
      -> signup.completed
      -> first_value.completed
      -> subscription.activated
      -> core_action.completed (持续发生)
```

| 指标 | 默认口径 | 权威来源 |
|---|---|---|
| 注册转化率 | 注册用户数 / 去重访客数 | Auth 数据库 + 产品分析 |
| 激活率 | 完成首次价值的注册用户数 / 注册用户数 | 标准运营事件 |
| 付费转化率 | 首次进入有效订阅的用户数 / 注册用户数 | 订阅与支付数据 |
| D1/D7/D30 留存 | 首次价值后对应日期再次完成核心动作的用户占比 | 产品分析 |
| MRR | 有效订阅按月折算后的经常性收入 | 支付 Webhook + 订阅读模型 |
| AI 毛利率 | （确认收入 - AI 估算成本）/ 确认收入 | 支付数据 + AI 用量 |
| 系统健康 | API、Action、Webhook 和任务的成功率与延迟 | 日志、监控和任务结果 |

产品可以覆盖 `first_value.completed` 和 `core_action.completed` 的业务含义，但必须
在项目文档中写明定义，改动定义时增加事件版本，禁止悄悄改变历史指标口径。

## 计划中的仓库形态

```text
src/core/services/telemetry.ts       事件与分析适配器契约
src/adapters/analytics/              PostHog、GA4、Umami、noop 等实现
src/services/telemetry.ts            生成后的分析服务装配
src/features/analytics/              同意状态、客户端身份与页面接入
src/features/operations/             运营驾驶舱、指标查询与每日快照
src/core/services/alerts.ts          告警契约
src/adapters/alerts/                 邮件、Webhook 与 noop 实现
src/db/schema/operations.ts          快照、规则和通知历史
```

业务模块继续只调用项目自己的服务和事件入口。供应商 SDK 与字段只能出现在对应
适配器目录，生成器按选择重建服务装配并删除未选实现。

## 核心验证矩阵

| 组合 | 部署目标 | 关键验证 |
|---|---|---|
| `minimal` + `noop` | Server | 无分析配置时可构建运行，不产生外部请求 |
| `saas` + PostHog | Vercel | 匿名访问、登录关联、注册到付费漏斗和同意撤回 |
| `saas` + 运营驾驶舱 | Docker Compose | 数据库指标、每日快照、空状态和管理员权限 |
| `ai-saas` + 运营驾驶舱 | Cloudflare Workers | 服务端事件、AI 用量、成本聚合和 Webhook 告警 |
| 自定义模块组合 | 全部 | 未选事件、页面、Schema、依赖和环境变量完整移除 |

自动测试使用注入式替身验证事件属性、身份关联、指标公式、时区、告警去重和适配器
契约。涉及外部分析服务和部署时，还要在隔离项目中做不含秘密输出的真实冒烟验证。

## 暂缓范围

- 团队空间、成员邀请和团队账单不作为当前 3.x 主线；事件信封预留可选
  `workspaceId`，等真实需求明确后再增加团队模块。
- 不自建完整事件仓库、客户数据平台、广告投放平台或会话回放系统。
- 不把 CMS、原生移动端、复杂工作流编辑器和公开适配器市场并入 3.x。
- 不承诺会计级利润报表；AI 成本和毛利用于运营判断，并明确估算来源。
- 不默认采集邮箱、姓名、IP、完整 User-Agent、提示词、生成结果和上传内容。

## 完成定义

一个里程碑只有同时满足以下条件才能标记为“已完成”：

1. 对应模块文档已经反映实际代码、指标口径和限制。
2. 事件校验、身份关联、指标计算、适配器契约或告警规则等核心逻辑具备单元测试。
3. 纯展示层不增加单元测试，运营页面通过人工或浏览器检查确认布局与交互。
4. 格式化、lint、严格类型检查、相关测试和生产构建全部通过。
5. 涉及供应商或部署目标时，已完成真实写入、查询或通知冒烟验证。
6. 改动已 commit 并推送，完成依据记录在模块文档中。

## 关键决策

| 日期 | 决策 | 原因 |
|---|---|---|
| 2026-08-01 | 3.x 主线调整为独立 SaaS 运营观测 | 独立开发者普遍缺少获客、激活、付费、留存和成本闭环 |
| 2026-08-01 | 收入和订阅指标以服务端业务数据为准 | 浏览器事件可能被拦截、重复或丢失，不能承担收入确认 |
| 2026-08-01 | `first_value.completed` 作为统一激活节点 | 不同产品核心价值不同，需要一个稳定且可由项目定义的接入点 |
| 2026-08-01 | 首批产品分析计划采用 PostHog，保留 GA4 | PostHog 覆盖产品漏斗与留存，GA4 继续承担流量和广告归因 |
| 2026-08-01 | 本地只保存业务事实、日聚合和告警历史 | 控制数据库体积、隐私风险和跨部署目标的维护成本 |
