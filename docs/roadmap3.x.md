## 项目目标

NextDevTpl 3.x 为独立 SaaS 预置一套可裁剪的运营观测能力。生成的项目可以回答：用户从
哪里来、在哪一步流失、是否完成首次价值、是否愿意付费、每个用户和每次 AI 请求是否有
合理毛利。数据留在生成项目自己的数据库和已选择的适配器中，不依赖 NextDevTpl 线上服务。

## 核心原则

1. 只采集能帮助决策的数据，不默认记录所有点击。
2. 行为事件来自产品分析；收入、订阅和积分来自服务端业务数据；错误与性能来自日志和监控。
3. 事件名称、版本和属性使用严格类型，模块只发布自己负责的事件。
4. 默认不采集密钥、Cookie、Authorization、邮箱、完整 IP、提示词、模型原始回复或上传内容。
5. 分析和告警故障不能阻塞注册、支付、积分和核心业务。
6. 未选择的适配器、依赖、环境变量、Schema 和路由必须从生成项目中删除。
7. 每个指标必须说明来源、公式、时间范围、时区和缺失状态；配置完成不能替代真实数据验证。

## M0 - v3.0 运营观测基线与埋点内核

建立供应商无关的 `telemetryService`，统一客户端和服务端事件封装、身份上下文、事件版本、
属性校验和失败降级。首批提供 `noop`、结构化日志、PostHog、GA4 和 Umami 适配器，并把旧
Google Analytics 接入迁入统一选择体系。事件属性使用严格类型和运行时校验。

## M1 - v3.1 标准运营事件与来源归因

在认证、营销、Dashboard、支付、订阅、积分、支持、后台任务和 API/Action 边界接入标准事件。
模板自动记录通用链路，同时保留 `first_value.completed` 与 `core_action.completed` 两个
明确产品接入点。首次来源、最近来源、UTM、匿名 ID、会话 ID、登录用户 ID、版本和部署环境
统一进入上下文，匿名访问可在登录后关联，但不会把邮箱等个人信息发送给分析供应商。

## M2 - v3.2 运营驾驶舱与指标聚合

新增可选 `operations` 模块，为管理员提供总览、漏斗、留存、产品使用、系统健康、收入和 AI
用量视图。低频或高成本查询可写入每日快照。每个指标区分 `zero-data`、`not-configured`、
`unauthorized`、`query-failed` 和 `partial`，不把陈旧快照冒充当前有效数据。

## M3 - v3.3 收入与订阅健康

从支付 Webhook、订阅状态和价格配置生成可审计的收入读模型，覆盖新增付费、MRR、付费转化、
续费、流失、退款和支付失败。浏览器端 `checkout.completed` 只用于用户路径分析，不作为收入
确认依据。金额统一保存货币和最小货币单位，月付与年付按明确规则折算 MRR。

## M4 - v3.4 AI 成本与毛利

扩展 AI 服务契约，返回模型、供应商、输入/输出/总 Token、耗时和用量覆盖状态。价格表按生效
时间版本化；无法取得真实 Token 时明确标记 `unavailable` 或 `estimated`。运营查询可按模型、
功能、用户和日期聚合请求量、成功率、延迟、积分收入、估算成本和毛利。提示词、原始回复和
上传内容不进入运营事件。

## M5 - v3.5 运营告警与自动化

为支付失败率、AI 成本和付费转化下降提供规则和通知。首批通知适配器为 `noop`、邮件和签名
Webhook，Webhook 可接入飞书、Slack、Discord 等通用入口。规则使用稳定去重键、连续触发次数、
冷却时间、独立恢复阈值和发送历史。M5 只做观察与通知，不自动退款、封禁用户、修改套餐或
关闭服务。

## M6 - v3.6 运营适配器兼容与稳定性

本阶段补齐适配器能力声明和部署组合验证：

- 检查 Server、Docker Compose、Vercel、Cloudflare Workers 的运行时、环境变量和绑定差异。
- 验证 `operations`、`analytics`、`mail`、`jobs` 和 `ai` 的选配组合，确认未选实现、依赖、
  Schema、路由和环境变量被完整裁剪。
- 记录 noop、PostHog、GA4、Umami、邮件和签名 Webhook 的能力矩阵，以及缺少配置时的状态。
- 在隔离项目和临时供应商目标中完成最小写入、只读查询和通知冒烟；输出不得包含秘密。
- 将兼容性结论、供应商限制和失败降级策略写入[运营适配器与兼容性](模块设计/运营适配器与兼容性.md)。

## M7 - 3.x 用户文档与发布收尾

同步 README、生成器参数、环境变量、内置中英文 `/docs`、隐私说明、指标字典、供应商配置、
运营驾驶舱、告警和故障排查文档。发布前重新运行格式化、lint、严格类型检查、测试、生产构建、
生成预设验证、兼容性矩阵和发布包检查，并记录最终支持范围与已知限制。

## 标准运营漏斗

```text
landing.viewed
      -> signup.completed
      -> first_value.completed
      -> subscription.activated
      -> core_action.completed（持续发生）
```

| 指标 | 默认公式 | 权威来源 |
|---|---|---|
| 注册转化率 | 注册用户数 / 去重访客数 | Auth 数据库 + 产品分析 |
| 激活率 | 完成首次价值的注册用户数 / 注册用户数 | 标准运营事件 |
| 付费转化率 | 首次有效订阅用户数 / 注册用户数 | 订阅与支付数据 |
| D1/D7/D30 留存 | 首次价值后对应日期再次完成核心动作的用户占比 | 产品分析 |
| MRR | 有效订阅按月折算后的经常性收入 | 支付 Webhook + 订阅读模型 |
| AI 毛利率 |（确认收入 - AI 估算成本）/ 确认收入 | 支付数据 + AI 用量 |
| 系统健康 | API、Action、Webhook、任务的成功率与延迟 | 日志、监控和任务结果 |

## 计划中的仓库结构

```text
src/core/services/telemetry.ts     事件与分析适配器契约
src/adapters/analytics/            PostHog、GA4、Umami、noop 等实现
src/services/telemetry.ts          生成后的分析服务装配
src/features/analytics/            同意状态、客户端身份与页面接入
src/features/operations/           驾驶舱、指标查询、快照和告警
src/core/services/alerts.ts        告警契约
src/adapters/alerts/               邮件、Webhook、noop 实现
src/db/schema/operations.ts        快照、AI 用量、告警和发送历史
```

业务模块只调用项目自己的服务和事件入口，供应商 SDK 与字段只出现在对应适配器目录。生成器
根据选择重建服务装配并删除未选实现。

## 完成定义

里程碑只有同时满足以下条件才可标记为“已完成”：

1. 模块文档反映实际代码、指标口径和限制。
2. 核心逻辑有单元测试，纯展示层不增加无意义的单测。
3. 格式化、lint、严格类型检查、相关测试和生产构建全部通过。
4. 涉及适配器或部署目标时，完成隔离的真实读写或通知冒烟验证。
5. 代码和文档以独立 commit 提交并推送，路线图记录对应证据。

## 暂缓范围

- 团队空间、成员邀请和团队账单不属于当前 3.x 主线；事件上下文预留 `workspaceId`。
- 不自建完整事件仓库、客户数据平台、广告投放平台或会话回放系统。
- 不把 CMS、原生移动端、复杂工作流编辑器和公开适配器市场并入 3.x。
- 不承诺会计级利润报表；AI 成本和毛利用于运营判断，并明确估算来源。
- 不默认采集邮箱、姓名、IP、完整 User-Agent、提示词、生成结果或上传内容。

## 关键决策

| 日期 | 决策 | 原因 |
|---|---|---|
| 2026-08-01 | 3.x 主线调整为独立 SaaS 运营观测 | 独立开发者普遍缺少获客、激活、付费、留存和成本闭环 |
| 2026-08-01 | 收入与订阅指标以服务端业务数据为准 | 浏览器事件可能被拦截、重复或丢失，不能承担收入确认 |
| 2026-08-01 | `first_value.completed` 作为统一激活节点 | 不同产品核心价值不同，需要由项目明确接入且稳定的节点 |
| 2026-08-01 | 首批产品分析采用 PostHog，同时保留 GA4 | PostHog 覆盖产品漏斗与留存，GA4 继续承担流量和广告归因 |
| 2026-08-01 | 本地只保存业务事实、日聚合和告警历史 | 控制数据库体积、隐私风险和跨部署维护成本 |
