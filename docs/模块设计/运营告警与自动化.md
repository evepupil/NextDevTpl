## 职责与边界

本模块负责计算规则、管理告警状态并发送通知。它只做观察与提醒，不自动执行退款、
封禁、价格调整、服务关闭等高风险业务操作。

## 结构与数据流

```text
当前指标 + 历史基线 -> 规则评估 -> 告警状态 -> email / webhook / noop
                                      |
                                  发送与恢复历史
```

## 关键决策

- 首批覆盖支付失败、Webhook/任务失败、错误率、AI 成本、余额异常和转化下降。
- 每条规则具备稳定幂等键、连续触发次数、冷却期和恢复条件。
- 通知失败记录状态并有限重试，不阻塞原始业务请求。
- 通用 Webhook 使用固定安全载荷和签名，URL 与密钥只存在服务端配置。
- 告警消息包含时间范围、当前值、阈值、数据来源和建议检查入口。
- 规则默认保守，真实流量不足时不启用基线异常判断。

## 当前实现

当前项目具备邮件、任务、结构化日志和 Sentry，但没有统一告警契约、经营指标规则、
冷却去重、恢复通知和发送历史。

## 验证方式

- 使用纯函数测试阈值、连续窗口、冷却和恢复状态机。
- Repository 测试覆盖重复执行与幂等更新。
- 适配器契约测试覆盖邮件、Webhook、超时和失败降级。
- 真实冒烟只使用隔离通知目标，不在日志输出 URL、签名或秘密。
