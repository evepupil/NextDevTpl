# 运营适配器与兼容性

> 模块定位：声明运营适配器能力，验证生成裁剪和四种部署目标的稳定性
>
> 对应代码：`src/core/services/manifest.ts`、`src/adapters/registry.ts`、
> `src/adapters/analytics/`、`src/adapters/alerts/`、`recipes/catalog.json`、
> `packages/create-nextdevtpl/src/`、`scripts/compatibility/`
>
> 所属里程碑：[M6 - v3.6 运营适配器兼容与稳定性](../roadmap3.x.md#m6)
>
> 当前状态：已完成（外部供应商按配置可用性记录）
>
> 最近更新时间：2026-08-02

## 职责与边界

本模块负责分析、告警以及相关服务适配器的能力声明、运行时约束、生成裁剪、契约测试和
部署验证。它记录供应商差异，不强行把 GA4 当成完整产品分析平台，也不把构建通过写成
供应商已经接通。真实供应商冒烟只使用最小的隔离读写或通知请求。

## 结构与数据流

```text
统一服务契约 -> 运行时 capabilities -> registry/catalog
                                      |
                                      v
                          生成器选择 -> 源码/依赖/env/Schema/路由裁剪
                                      |
                                      v
                           目标矩阵 -> 生成、迁移、lint、类型、测试、构建
```

- `ServiceAdapterManifest.runtime` 限制 Node、通用 Fetch 和 Workers 适配器的部署目标。
- 运行时适配器通过 `capabilities` 声明可用功能；`src/test/adapters/registry.test.ts` 检查
  每个注册适配器都暴露非空能力集合。
- `recipes/catalog.json` 是生成器裁剪的来源，`alerts` 作为独立服务族提供 noop、email 和
  webhook 三种告警实现。
- `scripts/verify-compatibility.mjs` 由 `tests/compatibility/matrix.json` 驱动，结构模式检查
  选中适配器、必需环境变量、Schema、部署文件和未选实现的删除；完整模式继续跑安装、迁移、
  lint、类型、测试、构建和健康检查。

## 能力矩阵

| 服务 | 适配器 | 运行时 | 关键能力 | 备注 |
|---|---|---|---|---|
| 分析 | noop | universal | 服务端事件契约 | 不产生外部请求 |
| 分析 | logger | universal | 服务端事件、结构化日志 | 不提供漏斗/留存查询 |
| 分析 | PostHog | universal | 客户端事件、服务端事件、身份关联 | 当前模板通过 Capture 写事件，查询留在本地运营读模型 |
| 分析 | GA4 | universal | 客户端事件、服务端事件、身份关联 | 用于流量和广告归因，不承诺完整产品分析 |
| 分析 | Umami | universal | 客户端事件、服务端事件、身份关联 | 轻量事件采集，查询能力由本地读模型承担 |
| 告警 | noop | universal | 可用契约 | 默认降级，不发送消息 |
| 告警 | email | universal | 邮件通知 | 依赖已选 Mail 适配器和 `EMAIL_FROM` |
| 告警 | webhook | universal | Fetch 通知、可选 HMAC-SHA256 签名 | 可连接飞书、Slack、Discord 等通用入口 |

运营页面的漏斗、留存和收入查询来自生成项目数据库与运营事件。分析供应商只承担事件
采集和归因，避免不同供应商查询口径不一致。

## 生成器裁剪规则

- 未选 `operations` 时删除 `src/adapters/alerts/` 和 `src/services/alerts.ts`；核心告警契约
  可以保留，因为它不导入供应商代码。
- 选中 `operations` 后，`alerts` 适配器固定在生成时选择；只保留选中的 email 或 webhook，
  以及用于配置缺失降级的 noop。其他告警实现、环境变量和依赖不进入生成项目。
- 未选分析适配器时，生成器保留内置 noop telemetry 服务，保证认证、支付和积分边界的
  埋点导入仍然可用；选中分析适配器时只保留对应实现。
- `validateCatalog()` 检查服务前缀、源码路径、运行时和目标兼容性；Workers 目标拒绝
  Node 专用适配器，非 Workers 目标拒绝 Worker Binding 适配器。
- 自定义模块未选 Dashboard 时，生成器保留登录保护并使用轻量 Dashboard 布局，避免导入
  已裁剪的 Dashboard 组件。

## 兼容性矩阵

结构矩阵共 8 组，包含原有四种部署基线和 operations 四目标组合：

| 组合 | 目标 | 结果 |
|---|---|---|
| `minimal-server` | Server | 结构通过 |
| `saas-docker` | Docker Compose | 结构通过 |
| `saas-vercel` | Vercel | 结构通过 |
| `ai-saas-cloudflare` | Cloudflare Workers | 结构通过 |
| `operations-server` | Server + alerts noop | 完整门禁通过 |
| `operations-docker` | Docker Compose + alerts webhook | 完整门禁通过 |
| `operations-vercel` | Vercel + alerts email | 完整门禁通过 |
| `operations-cloudflare` | Cloudflare + Umami + alerts webhook | Linux 原生完整构建通过 |

operations Server、Docker、Vercel 的完整生成项目均通过安装、迁移、lint、严格类型检查、
测试、生产构建和健康检查。Cloudflare 在 Windows 上会因 OpenNext 创建符号链接触发 EPERM；
同一项目复制到 WSL 原生 `/tmp` 后，Linux `cf:build` 通过，Worker 源文件为 2,278 bytes、
gzip 后 745 bytes，低于 3 MiB 免费限制。Windows 项目继续保留该已知限制，部署前使用 WSL 或
Linux CI。

## 真实供应商冒烟记录

记录时间：2026-08-02。请求均不输出密钥、响应正文或个人数据。

| 供应商/动作 | 结果 | 范围与限制 |
|---|---|---|
| Stripe `GET /v1/prices?limit=1` | 通过，HTTP 200 | 只读 API，未创建 Checkout、订阅或支付 |
| Resend `GET /domains` | 跳过 | 本机没有 `RESEND_API_KEY`，邮件适配器使用契约测试覆盖 |
| PostHog / GA4 / Umami API | 跳过 | 本机没有对应生产配置；Capture/Measurement Protocol/Umami 请求由适配器测试覆盖 |
| 告警 Email/Webhook | 跳过 | 没有隔离收件地址或 Webhook URL；邮件、HMAC 签名和失败降级由契约测试覆盖 |
| Cloudflare OpenNext | 通过 | WSL 原生临时项目完成构建，未启动 Worker、未部署远端资源 |

配置存在不等于接入成功。上线前需要在隔离项目重新执行对应供应商的最小读写或通知
冒烟，并把结果、时间、部署目标和供应商版本补进发布记录。

## 验证方式

- `pnpm test:run -- src/test/adapters/registry.test.ts src/test/architecture/generator-catalog.test.ts src/test/generator/selection.test.ts src/test/generator/generate.test.ts`
- `pnpm verify:compatibility:structure`
- `pnpm verify:compatibility --case operations-server`
- `pnpm verify:compatibility --case operations-docker`
- `pnpm verify:compatibility --case operations-vercel`
- Cloudflare 使用 WSL 原生路径执行生成项目的 `pnpm cf:build`。
- 真实供应商冒烟只使用隔离目标；日志和报告通过统一脱敏函数过滤 token、密钥、密码和数据库 URL。
