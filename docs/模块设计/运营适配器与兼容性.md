## 职责与边界

本模块负责产品分析与告警适配器的能力声明、生成裁剪、契约测试和真实冒烟。它不
强行抹平供应商差异，运营页面根据能力明确展示支持范围。

## 结构与数据流

```text
统一契约 -> 能力声明 -> 供应商实现 -> 生成 recipe -> 兼容矩阵
```

计划中的分析选择包括 `noop`、结构化日志、PostHog、GA4 和 Umami；计划中的告警
选择包括 `noop`、邮件和通用 Webhook。最终范围以实施时的官方文档、成本、运行时
和 API 能力复验为准。

## 关键决策

- 能力声明覆盖客户端事件、服务端事件、身份关联、漏斗、留存和查询 API。
- GA4 定位于流量和广告归因，不承诺完整产品分析查询。
- 未选适配器的 SDK、环境变量、客户端脚本和服务端代码全部删除。
- Cloudflare 组合只能使用 Fetch/Binding 兼容实现，禁止引入 Node 专用传输。
- 真实验证同时检查事件写入与指标读取，配置存在不能视为接入成功。
- 兼容结果记录供应商、版本、部署目标、时间和已知限制。

## 当前实现

当前 `analytics` 模块直接加载 GA，并把 Sentry 配置放在同一模块 recipe；日志在
Server、Docker/Vercel 与 Cloudflare 使用不同实现。产品分析和告警尚未进入服务
适配器注册表，也没有对应兼容矩阵。

## 验证方式

- 运行适配器契约、生成器裁剪和依赖边界测试。
- 为四种部署目标生成并构建代表性组合。
- 在隔离项目执行同意、写入、身份关联、查询和通知真实冒烟。
- 检查禁用分析时没有客户端脚本、Cookie 或外部网络请求。
