## 职责与边界

本模块负责定义供应商无关的运营事件契约，以及浏览器和服务端共同使用的事件
信封。它不计算收入、不渲染运营页面，也不替代日志和 Sentry。

分析服务不可用时，业务流程继续完成。事件发送失败进入安全日志或内部计数，禁止
把供应商异常直接返回给最终用户。

## 结构与数据流

```text
业务模块 / 页面 -> telemetryService -> noop / logger / PostHog / GA4
                         |
                         +-> 类型校验、身份上下文、同意检查、脱敏
```

事件信封计划包含 `eventId`、`name`、`version`、`occurredAt`、`source`、
`environment`、`release`、匿名或登录身份、会话、请求、Locale、来源和经过校验的
属性。服务端不信任客户端传入的用户、金额、套餐和权限字段。

## 关键决策

- 事件名称和属性都使用严格 TypeScript 类型与 Zod 校验。
- 客户端分析在用户同意后启用，撤回同意后停止发送并清理供应商标识。
- 服务端必要运营事件只携带内部 ID 和业务状态，禁止附带个人信息与原始内容。
- `noop` 始终可用，未配置分析服务时生成项目仍能正常运行。
- 现有 `logEvent()` 逐步迁移到统一服务，日志继续作为诊断出口之一。
- 同一个业务结果只在权威完成点发出一次，并携带稳定幂等标识。

## 当前实现

当前 `analytics` 模块只在同意后加载 Google Analytics；`logEvent()` 提供有限的
事件名联合类型，属性仍是任意对象；日志、Sentry、API 和 Action 耗时分别存在。
供应商无关的事件服务、事件版本、身份关联和产品分析适配器尚未实现。

## 验证方式

- 单元测试事件名称、属性 Schema、版本和上下文合并。
- 测试同意、拒绝、撤回、匿名和登录身份状态。
- 通过适配器契约测试检查映射、批量、超时和失败降级。
- 扫描事件属性，拒绝密钥、Cookie、Authorization 和受限内容字段。
- 生成 `noop` 组合，确认没有分析依赖、环境变量或外部请求。
