## 职责与边界

本模块维护三层用户入口：仓库 README 用于快速判断和首次创建项目，生成器
README 用于查询 CLI 参数，应用内 `/docs` 用于从本地开发到生产部署的完整操作。
研发过程、实现提交和验证证据继续放在 roadmap、模块设计和 Release 文档中，
避免把内部记录混入使用手册。

## 结构与数据流

用户先运行 `create-nextdevtpl` 选择预设、模块、适配器和部署目标。生成器把实际
选择写入 `nextdevtpl.generated.json`，并按选择生成 `.env.example`、服务入口、
数据库 Schema 和部署配置。内置文档要求用户先查看这份清单，再按照所选能力
填写环境变量和执行对应部署步骤。

```text
README -> create-nextdevtpl -> nextdevtpl.generated.json
                              -> /docs 配置与功能操作
                              -> /docs 部署与升级
```

## 关键决策

- 文档只描述当前代码与发布包已经支持的行为。
- 中英文页面保持相同信息结构、命令和限制。
- 服务能力同时说明统一入口和供应商适配器，减少替换服务时的业务改动。
- 部署文档按 Server、Docker Compose、Vercel、Cloudflare Workers 分开说明。
- 生成器当前使用命令行参数；无参数交互选择暂未实现，文档不宣称存在向导。
