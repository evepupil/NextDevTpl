## 职责与边界

本模块负责向模板使用者解释如何选择、接入、验证和运营 3.x 能力，并记录稳定版
兼容证据。文档只描述已经实现的功能，规划内容继续保留在 roadmap 和模块设计中。

## 结构与数据流

```text
README -> 生成器选择 -> 环境与隐私配置 -> 事件接入 -> 驾驶舱/告警 -> 故障排查
```

## 关键决策

- 中英文文档保持相同指标名称、公式、限制和验证步骤。
- 提供默认事件字典，并明确首次价值和核心动作必须由项目定义。
- 每个供应商说明配置、能力、数据延迟、保留和故障状态。
- 隐私文档覆盖同意、撤回、内部 ID、禁止字段和数据删除。
- 发布说明区分已实现能力、实验能力和计划能力。
- 用户必须通过真实事件和查询确认接入，不能只检查环境变量。

## 当前实现

M7 已同步以下用户入口：

- 根 README、生成器 README、生成后的模板 README 和 CLI 帮助；
- 中英文 `/docs` 的首页、生成器、模块、服务适配器、配置、可观测性、后台任务、
  运营工具包和部署说明；
- 中英文隐私政策和 Cookie 政策中的匿名标识、同意、脱敏和 AI 用量边界；
- 运营事件字典、指标公式、状态语义、供应商配置、Cron 调度、告警规则和故障排查；
- 生成器 `--alerts` 入口及告警/分析适配器的裁剪说明。

文档明确区分服务端收入事实、浏览器产品事件、日志健康指标和估算 AI 成本；未配置、
无数据、查询失败和权限不足不会被写成有效的 0。

## 验证方式

- 对照源码、recipe、环境变量和生成器参数检查文档。
- 检查中英文页面、导航和内部链接。
- 运行全部项目门禁、发布包检查和官方组合验证。
- 按文档从空项目完成一次真实埋点、查询、驾驶舱和通知验收。

M7 还验证了 `--alerts webhook` CLI 解析、运营文档被模板快照收录，以及四目标
operations 兼容矩阵与发布包检查。最终门禁结果如下：

- `pnpm format`、`pnpm lint`、`pnpm typecheck` 全部通过；
- `pnpm test:run`：45 个测试文件、410 个测试全部通过；
- `pnpm build`：108 个页面生成成功；
- 五组生成预设分组通过完整安装、迁移、lint、类型、生成测试、构建和健康检查：
  `minimal`（15 页面）、`saas`（90 页面）、`saas-docker`（90 页面）、`ai-saas`
  （103 页面）、`custom`（16 页面）；
- `pnpm verify:compatibility:structure`：八组兼容矩阵全部通过；
- `pnpm release:check`：`create-nextdevtpl@2.6.0` 发布包 488 个文件通过检查；
- Cloudflare 运营组合在 WSL 原生目录完成安装、迁移、lint、类型、测试和 `cf:build`，
  Worker 产物 2,278 bytes、gzip 746 bytes；Windows 预检的符号链接权限限制按已知限制记录。
