## 职责与边界

运营驾驶舱负责查询、聚合和展示运营指标。它只向管理员开放，不向普通用户暴露
全站数据，也不保存完整浏览事件副本。

## 结构与数据流

```text
产品分析查询 ----+
Auth/积分/工单 ---+-> 指标查询 -> 每日快照 -> /admin/operations
日志与任务结果 ---+
```

首页展示当前周期与上一周期对比；漏斗展示访问、注册、首次价值和付费；留存展示
D1/D7/D30；产品使用展示核心动作和功能采用；健康视图展示 API、Action、Webhook
与任务成功率。

## 关键决策

- 指标定义集中管理，页面不能各自拼接公式。
- 高频或高成本查询按日生成快照，并保留来源与生成时间。
- 当前数据和快照数据在界面上明确区分。
- 状态统一为 `ready`、`zero-data`、`not-configured`、`unauthorized`、
  `query-failed` 或 `partial`。
- 供应商不支持的指标显示能力缺失，不使用零值掩盖。
- 日期范围和统计时区由管理员选择，默认使用项目配置时区。

## 当前实现

现有 Admin 页面可以查看用户、积分、订阅和工单的局部状态，但没有统一运营模块、
指标字典、趋势、漏斗、留存、每日快照和外部分析查询。

## 验证方式

- 单元测试指标公式、日期边界、时区、对比周期和缺失状态。
- Repository 测试覆盖快照幂等写入与重复生成。
- 权限测试确保普通用户无法访问运营数据。
- 使用注入式分析查询替身测试完整、空、部分和失败结果。
- 运营页面只做浏览器与人工视觉检查，不为纯布局增加单元测试。
