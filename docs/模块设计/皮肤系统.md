# 皮肤系统

> 模块定位：定义皮肤包，让生成项目的长相可以整套替换；功能代码由核心提供，所有皮肤共用
>
> 对应代码（规划）：`src/skin/`（当前皮肤；模板仓库中即默认皮肤）、`src/core/skin/`、
> `src/components/ui/`（基础组件）、`tests/fixtures/skins/`（测试皮肤）、
> `packages/create-nextdevtpl/`（皮肤解析、校验与套用）、
> `scripts/sync-stylekit-palettes.mjs`（StyleKit 配色同步）
>
> 所属里程碑：[M2 - v4.2 皮肤包与默认皮肤](../roadmap4.x.md#m2)、
> [M3 - v4.3 生成器选择皮肤](../roadmap4.x.md#m3)、
> [M4 - v4.4 StyleKit 免费配色](../roadmap4.x.md#m4)、
> [M6 - 4.x 皮肤制作文档与发布](../roadmap4.x.md#m6)
>
> 当前状态：未开始
>
> 最近更新时间：2026-11-06

## 职责与边界

皮肤系统负责：

- 皮肤包的组成、目录和清单格式。
- 规矩检查：皮肤里能放什么、能引用什么、必须声明什么。
- 默认皮肤（现有界面）和买家可调的变量。
- 生成项目时解析、校验、套用和记录皮肤（与[项目生成器](项目生成器.md)共同负责）。
- StyleKit 免费配色的快照与套用。
- 中英文皮肤制作指南。

皮肤系统不负责：

- 页面拆分和视图约定的定义，见[视图契约](视图契约.md)。
- 纯前端导出，见[纯前端导出](纯前端导出.md)。
- 皮肤的销售、授权签发和分发服务；这些不在本仓库实现。
- 具体某一套付费皮肤的制作。

## 皮肤的四层

| 层 | 内容 | 谁来改 |
|---|---|---|
| 变量层 | 明暗两套颜色、圆角、阴影、间距、字体 | 皮肤作者定义；皮肤声明的可调变量由买家修改 |
| 组件层 | 基础组件（按钮、输入框、卡片、弹窗、表格等）的形状和交互手感 | 皮肤作者 |
| 页面层 | 17 个页面视图和营销、登录、控制台三组外壳，可以整页重写 | 皮肤作者 |
| 素材与说明 | 插图、图标、配图、字体文件；一份给 AI 看的风格说明 | 皮肤作者 |

管理后台、文档站和演示页不做整页换皮，但使用同一套基础组件和变量，会跟随皮肤的变量层和
组件层变化。

## 结构与数据流

### 皮肤包目录

```text
<皮肤包>/
├── skin.json     清单：名称、版本、兼容的 NextDevTpl 版本、支持的模块、可调变量、
│                 是否支持 StyleKit 配色、额外依赖、素材清单、文件哈希
├── tokens.css    变量层：明暗颜色、圆角、阴影、间距
├── fonts.ts      字体加载
├── ui/           组件层：覆盖的基础组件，未覆盖的沿用默认
├── layouts/      营销、登录、控制台三组外壳
├── views/        页面视图，按拥有模块分组；index.ts 导出全部视图
├── messages/     皮肤自带文案（可选，独立翻译命名空间）
├── demo/         纯前端导出用的演示数据（可选，缺省使用核心的通用演示数据）
├── assets/       素材文件
└── DESIGN.md     给 AI 看的风格说明
```

### 生成时的数据流

```text
选择皮肤：内置 / 本地目录 / 远端皮肤包
   │
   ▼
获取：远端包只走 HTTPS，凭证从环境变量读取；下载后核对包哈希和清单内文件哈希
   │
   ▼
校验：清单格式、兼容版本、支持的模块覆盖所选模块、目录白名单、引用规则、
      视图完整性、素材授权
   │
   ▼
套用：替换 src/skin/；按文件覆盖 src/components/ui/ 中声明的基础组件；
      合并依赖、文案、字体和素材；按所选模块裁剪皮肤视图
   │
   ▼
可选：套用 StyleKit 配色（仅限声明支持配色的皮肤，默认皮肤支持）
   │
   ▼
记录：nextdevtpl.generated.json 写入皮肤名称、版本、来源类型和包哈希，不含凭证
   │
   ▼
继续原有流程：路由与模块裁剪、服务装配、可选安装
```

### 生成项目中的运行方式

- 路由与分组布局从 `@/modules/skin-views` 取得所选模块的视图；组合入口将
  `@/skin/views/<模块>` 中的页面与外壳统一按编号公开，外壳实现可放在 `src/skin/layouts/`。
- `src/app/globals.css` 引入 `src/skin/tokens.css`；根布局从 `@/skin/fonts` 加载字体。
- 生成项目只包含一套皮肤，运行时不切换皮肤。

## 规矩检查

生成器拒绝不合规的皮肤包；模板仓库内用受限引用规则约束 `src/skin/`。检查项：

1. 目录白名单：只允许上面列出的文件和目录。远端包解包时拒绝绝对路径和跳出目录的条目。
2. 引用规则：皮肤文件不得引用数据库、适配器、服务、各模块的服务端实现或 `server-only`
   模块；只能引用视图约定、无界面表单逻辑、基础组件、路由与国际化工具，以及清单声明的
   依赖。
3. 视图完整性：皮肤导出的视图集合必须满足所选模块登记的全部视图类型；皮肤未覆盖某个所选
   模块时直接拒绝，不混用默认皮肤的视图。
4. 业务数据：价格、套餐、积分数量不得写死在皮肤里，由验收清单检查。
5. 素材授权：每个素材在清单里写明作者、来源和授权；缺失则拒绝。内置皮肤不得包含第三方
   品牌的标识、名称、插图、图标、产品截图和文案。
6. 依赖：额外依赖必须在清单中声明并锁定版本，不得与核心依赖的主版本冲突。
7. 兼容版本：清单声明兼容的 NextDevTpl 版本范围，不满足则拒绝。

## 可调变量

- 清单声明可调项和取值范围：品牌色、标题与正文字体（从清单列出的候选中选择）、圆角档位、
  默认明暗。深色专属等特殊皮肤可以只开放其中一部分。
- 生成项目里可调变量集中在一处，修改后不影响皮肤的其余部分。
- 提供对比度检查命令：检查正文与背景、主色与主色文字、弱化文字与背景等关键组合是否达到
  4.5:1。

## 默认皮肤与测试皮肤

- 默认皮肤由 M1 拆出的视图和外壳、现有 24 个基础组件、`globals.css` 中的
  “Engineered Spec-Sheet” 变量和 Geist 字体组成，外观与 v3.0.0 一致，支持全部可调变量和
  StyleKit 配色。
- 模板仓库的 `src/skin/` 就是默认皮肤，仓库可以直接运行，发布快照与源码同源。
- 测试皮肤放在测试目录，刻意使用不同的变量和版式（例如直角、粗边框、单色、顶部导航替代
  侧栏），替换全部视图，只用于验证约定和生成流程，不随发布包分发。

## StyleKit 免费配色

- 来源：StyleKit 公开主题接口，每套风格提供明暗两套颜色、圆角、图表色和侧栏色，MIT 许可。
- 快照：由同步脚本拉取并转换成统一的颜色格式，记录快照日期和来源后提交到仓库；发布时只
  打包已提交的快照，生成时不联网。
- 套用：按风格名替换默认皮肤的颜色变量和圆角；快照里没有的变量（成功色、警告色、背景网格线
  和两层光晕）按规则从主色和前景色派生。
- 对比度：套用后检查关键组合，不足 4.5:1 时输出提示，不阻断生成。
- 署名：生成项目附带 StyleKit 的 MIT 许可声明。

## 远端皮肤包

- 生成器只提供通用能力：通过 HTTPS 下载、携带授权凭证、核对哈希、解包和校验。不内置任何
  特定的销售或授权服务地址。
- 凭证只从环境变量读取，以请求头发送；不出现在命令行参数、日志和生成结果中。
- 下载有超时和大小上限；任何一步失败都按现有规则回滚本次新建的目录。

## 皮肤制作指南（M6）

指南面向自己做皮肤的用户，内容包括：

- 视图约定参考、皮肤包目录与清单、规矩检查、可调变量和打包方式。
- 验收清单：全部页面明暗 × 电脑/手机截图；注册、登录、付款测试环境和积分扣减冒烟；对比度
  检查；业务数据未写死。
- 素材授权与去品牌检查：可以借鉴参考网站的风格（配色基调、字号节奏、版式节奏、动效手感），
  不得包含对方的标识、名称、插图、图标、产品截图和文案。
- 参照网站制作深度皮肤的建议流程：采集参考页面截图与结构，提炼变量，写皮肤规格（每个页面
  借鉴哪个区块的版式、换成自己的文案和素材），实现，验收。

## 关键决策

- 皮肤在生成时确定：选中的皮肤落到 `src/skin/`，生成项目只含一套皮肤。
- 模板仓库的 `src/skin/` 就是默认皮肤，延续“完整模板在仓库根目录开发、发布快照同源”的
  决策。
- 基础组件保留在 `src/components/ui/`，皮肤按文件覆盖；管理后台和文档站因此跟随皮肤的
  基础组件。
- 皮肤必须覆盖全部所选模块的视图，不与默认皮肤混用，避免同一个项目出现两种长相。
- 规矩检查在生成器和仓库 lint 两处执行。
- 开源仓库不实现任何收费逻辑，远端皮肤只提供通用下载与校验。
- StyleKit 配色快照手动同步并提交，发布只打包已提交版本。
- 去品牌检查列入验收清单和内置皮肤的规矩检查。

### M2 实施约定

以下为开工规格，M1 验收通过后实施；当前不据此标记完成。

#### 清单与版本

- 皮肤清单的解析、文件检查和打包逻辑放在生成器的 `src/skins/` 下，按职责拆文件；应用
  运行时不依赖这些代码。皮肤清单只解析数据，不执行皮肤的脚本来获取登记信息。
- 清单包含格式版本、稳定编号、名称、严格语义版本、兼容范围、支持的模块、可调项、
  是否支持配色、额外依赖、素材说明和文件哈希。额外依赖必须使用明确版本。
- 模板兼容版本与视图接口版本保存为模板核心的一份 JSON 数据；生成器读取模板中的这份
  数据，不用 CLI 自身版本推断兼容性。4.x 开发期间目标版本为 `4.0.0`、视图接口版本为 `1`；
  M6 发布时再统一核对包版本。路线图中的小阶段编号不代表已经发布了对应 npm 版本。
- 沿用当前按模块导出 `views` 的接口。清单的 `viewEntries` 将模块编号映射到包内相对入口，
  默认皮肤沿用 `views/<模块>/index.ts`，其他皮肤可自行组织目录；
  其具名 `views` 为显式对象，键对应核心登记的稳定编号；不允许用动态计算或对象展开隐去
  视图清单。实现函数和布局内部可以自由组织，参数兼容性继续由生成后的严格类型检查保证。
- 校验器按核心登记的所选视图检查缺项、重复和越权登记，不能通过导入并执行组件来发现视图。
  普通版与前端演示版使用同一份视图参数类型。

#### M2 接口定稿

- 模板版本唯一来源为 `src/core/skin/version.json`，内容为
  `{ "templateVersion": "4.0.0", "viewApiVersion": 1 }`。应用核心再导出该数据；
  生成器只从实际模板读取，不从 CLI 包版本推断。
- 静态解析使用直接运行依赖：TypeScript `5.9.3`、PostCSS `8.5.6`、
  postcss-value-parser `4.2.0`、semver `7.7.3`。版本固定并写入锁文件；不依赖传递安装。
  M2 不处理归档解包，M3 再选有维护的归档库。
- 清单格式版本为 `1`；必填字段为 `schemaVersion`、`id`、`name`、`version`、
  `compatibility`（`template` 范围、`viewApi` 整数）、`modules`、`viewEntries`、
  `uiOverrides`、`customization`、`supportsPalettes`、`dependencies`、`assets`、`files`。
  清单拒绝未知字段，字符串和集合必须有边界，版本必须是严格且已发布的语义版本。
- `viewEntries` 的键等于声明支持且拥有视图的模块；模块无视图时不伪造空入口。
  每个入口位于 `views/` 下，值为 `.ts` 或 `.tsx` 文件，登记值只能是标识符或静态属性引用。
  允许类型断言和 `satisfies` 外包装，拒绝对象展开、计算属性、重复键和运行时计算。
  只要求覆盖所选模块；不支持所选模块时立即拒绝。类型检查仍负责组件参数的兼容性。
- `uiOverrides` 将稳定的基础组件文件名映射到 `ui/` 下的实际文件；目标限定为模板已有组件，
  不允许覆盖任意应用路径。24 个现有基础组件保持唯一实现，另加入通用套餐徽标。
- `customization` 声明品牌颜色变量、圆角范围、字体候选和默认主题可选项；
  `config.ts` 提供可序列化的默认配置，`fonts.ts` 只导出字体类名，应用基线不依赖具体字体包。
  字体统一使用 `--font-skin-sans`、`--font-skin-heading`、`--font-skin-mono` 接口，
  默认皮肤的变量继续解析到原 Geist 字体，完整保留中文回退顺序。
  清单只保存候选范围，实际默认主题与字体选择只放在 `config.ts`；字体加载输出类名与三项
  CSS 变量。全局补齐 `--font-heading` 映射，标题消费该变量；默认值仍与原正文字体相同。
- 文件清单 `files` 为相对路径到小写 SHA-256 的映射，覆盖包内全部普通文件，唯独排除
  `skin.json`；缺失、多余、大小写冲突或未声明的文件一律拒绝。声明的 UI 覆盖文件也在其中。
  目录包指纹按路径排序，对每项的 UTF-8 路径、零字节、文件哈希和换行依次计算 SHA-256；
  清单另做稳定键序列化后参与包指纹，避免只改变入口或授权声明却复用原指纹。
- 素材逐项声明编号、种类（文件、依赖、内联）、作者、来源、许可与用途；文件素材须能解析到
  包内文件，字体和图标依赖声明上游包名与版本。全部素材文件都须有声明；Google 登录标识
  另按功能用途记录官方品牌规范来源。对外包路径、日志和报错均不得包含凭证。
- 稳定共享 UI 工具入口为 `@/components/ui-utils`，原工具入口保留兼容导出。
  文档布局通过营销模块的稳定服务端包装取得登记的 `marketing.header` 视图；页头的客户端
  包装调用公开控制器，再将用户、导航等结果交给纯显示实现，服务端不传递普通函数。
  客户端包装不导入包含服务端页面的完整视图聚合。该视图作为 `component` 加入营销登记，
  相应扩展视图种类校验；文档站的整页布局仍留在核心。
  通用套餐徽标移至 `src/components/ui/plan-badge.tsx`，旧模块导出保留兼容。
- 引用白名单按明确入口与清单依赖判断，所有相对引用解析到真实文件；检查静态导入、类型导入、
  重新导出、动态导入和 `require`，非静态模块名拒绝。CSS 通过 PostCSS 与值解析器检查
  `@import` 和 `url()`；拒绝越界引用、远端加载和未声明素材，允许锚点及明确的内联数据。
  Node 内置模块、服务端标记、数据库、供应商 SDK、动作和服务入口即使声明为依赖也拒绝。
- 全局 CSS 保持原三个库的导入顺序，其后引入 `../skin/tokens.css`；变量仍处于原有普通层级。
  映射、文档适配、基础样式和减少动态偏好留在全局入口。字体类名放到原根布局相同位置；
  核心主题管理接收配置，默认继续跟随系统。
- M2 提供内部的校验、打包和套用接口，供默认皮肤检查和真实测试皮肤验收调用；
  CLI 的来源选择、下载和失败回滚由 M3 接入。测试皮肤全部视图自行实现，实际操作公共控制器。
- 独立规格复核确认当前 64 个 TS/TSX 文件解析约需 137 毫秒，语法诊断为零。跨平台哈希路径
  固定用 `/`，按 UTF-8 字节排序；文件按原始字节计算，清单稳定序列化不含 BOM。

#### 变量、字体与基础组件

- `tokens.css` 接收当前明暗颜色、圆角和与视觉风格相关的工具类，保留其默认值与优先级。
  Tailwind 映射、应用基线、文档兼容规则和减少动态偏好的处理保留在应用全局样式中。
  不趁拆分删除现有工具类或改间距、断点、字距。
- 买家可调的品牌色、标题与正文字体、圆角集中在皮肤文件的明确区域；默认主题通过皮肤
  配置提供。默认皮肤继续使用当前字体、字体回退和 `system` 主题，迁移前后截图一致。
- `fonts.ts` 提供根布局消费的字体类名和变量；字体加载属于皮肤。核心 Provider 继续负责
  主题切换和文档环境，只接收皮肤配置，不把 Provider 本身移入皮肤。
- 24 个基础组件继续在 `src/components/ui/`；皮肤只按明确文件覆盖，不维护第二套默认组件。
  类名合并函数提供狭窄的 UI 工具入口，现有核心引用可保留兼容再导出，避免无关导入大迁移。

#### 引用边界

- 允许核心视图类型、功能模块的公开 `/view` 控制入口、明确的基础 UI、路由和国际化工具、
  皮肤内部文件及已声明的 UI 依赖。数据库、供应商 SDK、适配器、产品动作、服务端取数入口、
  Node 内置运行时和 `server-only` 标记禁止由皮肤引用。
- M1 约定的 `@/modules/view-runtime` 是明确的客户端控制入口，只公开工作区、余额和套餐的
  无界面行为；保持这个窄入口，不开放任意组合层路径，也不另造一套布局选择系统。
- 站点信息、导航、社交链接、价格与数量通过功能模块的数据或控制入口提供，皮肤不任意导入
  `config`。需要跨服务端传递的结构不能含普通函数或图标组件引用；客户端控制结果可含 UI 引用。
- SEO 结构化数据归路由或核心取数/元数据流程，不要求皮肤实现作者自行重复。营销入场效果
  属于视觉层，可放在默认皮肤内部；不将整个 `components/`、`features/shared` 或 `lib/` 目录
  放入许可范围。
- 语言、明暗、Cookie 偏好等公共控件按数据/行为与视觉的职责整理为明确入口，保留当前交互。
  不通过宽泛的 shared 聚合入口绕过引用检查。
- 用结构化的源码与 CSS 解析器检查静态/动态导入、重新导出、相对路径和 CSS 引用；不能只用
  文本匹配推断边界。校验不运行皮肤代码，也不把它描述为对第三方前端代码的隔离沙盒。

#### 文件、素材与哈希

- 来源文件只允许规约列出的目录和文件；拒绝符号链接、越界路径和未声明的可执行入口。
  每个普通文件的哈希独立计算，清单自身不递归计算自身哈希。默认皮肤的哈希可由工具重建，
  不手工维护；应用运行和买家修改样式无需依赖生成器。
- 本地品牌素材注明仓库来源与许可。字体和图标依赖分别声明上游版本、来源和许可；不能仅凭
  仓库 MIT 许可推定第三方字体或商标已获授权。
- 功能所需的官方登录标识单列用途和官方品牌规范依据，与借鉴设计时禁止携带的装饰性第三方
  品牌素材区分。保留默认 Google 登录按钮原样，禁止把其他产品的标识或截图作为皮肤装饰。
- 未被当前界面引用的脚手架图形不纳入默认皮肤素材；现有 OG 路径问题保持独立记录，不借
  打包工作悄悄改掉默认页面表现。

  纯展示层依旧通过截图验收，不写配色或类名快照单测。
- 测试皮肤实现全部视图及其控制逻辑接线，采用明显不同的版式和视觉变量；不调用默认皮肤的
  页面充当替换，也不作为用户可选的运行时模式。测试用界面仍须能操作登录、设置和工单等流程。
- 先对 M2 清单和引用检查编写独立测试，再用隔离的生成项目证明默认皮肤与测试皮肤均可安装、
  类型检查和构建。默认皮肤继续对照 M0 冻结截图，测试皮肤验证全部路由和关键操作可运行。
