## 职责与边界

面向项目使用者说明完整与演示模式、皮肤、配色和升级；面向皮肤作者说明目录、视图约定、
数据边界、依赖、来源、许可和浏览器验收。文档与实际 CLI 参数、生成记录保持一致。
发布工具验证包内容与独立运行，不自动发布 npm、不部署站点、不自动覆盖已有项目。

## 结构与数据流

双语 README 提供入口，站内文档解释具体操作，升级指南使用重新生成的对照项目人工合并。
发布检查先准备纯合同镜像、组装模板并编译生成器，然后读取 npm pack 清单；核对候选版本、
公开发布设置、全部运行时脚本、演示源码及版本元数据，拒绝环境文件、测试与本机缓存。

兼容矩阵包含 12 个 case：八个原有完整组合、本地皮肤、完整配色、演示与演示配色。持续集成
构建四种部署目标及新增四种组合，质量任务运行全部单测、快照与发布检查；远端来源由真实本地
HTTPS fixture 的来源测试覆盖，不依赖公共下载服务。

完整项目验收执行安装、初始迁移生成、静态、类型、冒烟、构建和适用健康检查；演示项目在白名单
进程环境内生成和运行，跳过数据库步骤。各组合生成 JSON 回执。真实打包 CLI 在仓库外安装 tarball，
调用已安装 CLI、默认安装项目依赖并构建，检查脱敏与来源隔离。

## 关键决策

- 生成器候选版本为 `4.0.0`；根私有开发仓库保持 `0.1.0`。候选版本与实际 npm 发布状态分别记录。
- 发布检查读取 4.x 路线图。当前版本字段用于候选一致性校验，另列 npm 已发布版本，避免误解。
- 演示模式不传预设或后端服务选项；记录八个前端模块时使用独立视图模块列表。
- 皮肤版本元数据与动态收集的运行时文件都是必需项，防止清单表面通过但用户生成失败。
- 子进程等输出流关闭后再拼接和脱敏，错误不输出凭据；临时目录清理先核对范围及目录身份，
  无法确认时保留并写明原因。
- 实际 npm 发布在可审查的 tarball、校验值、门禁及远端结果齐备后由用户最后确认。

## 验证方式

- 项目格式、静态、严格类型、完整单测和根生产构建。
- 12 组合结构验证，代表组合完成真实安装构建；持续集成八组构建全部通过。
- 149 套离线配色快照校验及已有来源回滚测试，不重复宣称未经运行的外部兼容性。
- 发布清单检查及仓库外真实 tarball 的完整与演示配色项目生成运行，日志与 JSON 回执保留。
- 文档双语参数及相对链接核对；README 与生成项目所选能力的边界明确。
- npm 发布后单独核对 registry 版本与安装，取得发布证据后才将 M6 标记完成。
