## 职责与边界

生成器负责收集选择、解析依赖、复制文件和输出配置。生成器不参与线上运行，
也不替用户维护生成后的代码。

## 结构与数据流

```text
CLI 参数或交互选择
        |
        v
recipes/catalog.json       模块、事件、适配器、预设和部署目标清单
        |
        v
选择解析器                 依赖闭包、冲突和运行时兼容检查
        |
        v
模板复制 -> 路由/模块裁剪 -> 注册表/Schema/翻译/服务装配重建
        |
        v
独立项目 + nextdevtpl.generated.json + 可选 pnpm install
```

仓库开发时直接使用当前源码作为模板来源。发布 `create-nextdevtpl` 前，`prepack`
脚本根据 `templates/base/manifest.json` 组装只读模板快照和 recipe 清单，避免手工
维护第二套源码。生成结果不包含生成器包、roadmap、测试数据库配置和完整模板的
迁移历史。

## 关键决策

- 提供 `minimal`、`saas`、`ai-saas` 三个官方预设。
- 支持无交互参数，方便 CI 和自动化使用。
- 使用 JSON、AST 或框架配置 API 修改结构化文件，避免脆弱的字符串替换。
- 生成结果不依赖 `create-nextdevtpl` 包。
- 目标目录必须为空或不存在；生成失败只回滚本次新建的精确目录。
- M3 只记录部署目标和 Binding 需求。Docker/Vercel 配置由 M4 生成，Cloudflare
  Binding 类型与运行时注入由 M5 完成。
- 完整模板继续在仓库根目录开发；发布包通过自动快照保持模板与源码同源。

## 当前实现

`create-nextdevtpl` 已作为独立 workspace 包实现。CLI 支持官方预设和自定义
模块，服务适配器与部署目标均可通过参数覆盖：

```text
create-nextdevtpl <directory>
  --preset minimal|saas|ai-saas|custom
  --modules auth,dashboard,...
  --target server|docker|vercel|cloudflare
  --payment/--storage/--mail/--ai/--alerts/--analytics/--jobs/--rate-limit <adapter>
  --no-install --yes
```

选择解析器会计算模块依赖闭包，校验适配器能力分类和 Node/Worker 运行时兼容，
并拒绝非空目标目录。生成失败时只删除本次新建的目标目录，已有空目录不会被
整体删除。

自定义组合不包含 `auth` 时只能生成公开模块和 `dashboard` 壳；`admin`、`blog`、
`credits`、`marketing`、`payment`、`pseo`、`settings`、`storage`、`subscription`
和 `support` 会被选择校验拒绝，因为这些模块依赖登录身份。无认证项目会移除认证
路由、认证 API、Better Auth 和 safe-action 文件，改用不读取用户身份的 Dashboard
布局与中间件，并保留 i18n 和请求限流能力。

当组合同时不包含认证和分析时，生成器会输出公开 Dashboard 页面、空的 Schema
导出和内置 telemetry fallback；这样生成项目仍可冻结安装、生成初始迁移、类型检查
和生产构建，不会留下失效的认证导入或空 Schema 的 Drizzle 类型错误。

生成流程已经覆盖以下内容：

- 删除未选 feature、路由目录、Schema 文件、适配器源码和供应商 SDK；
- `operations` 模块可选择 `alerts:noop`、`alerts:email` 或 `alerts:webhook`，只保留
  选中的告警实现；未选 `operations` 时告警服务和适配器整族删除；
- 重建模块注册表、Schema 汇总、翻译、`.env.example`、服务装配和包信息；
- 按选择重建 Locale、Dashboard 与 sitemap 组合入口；
- 支付 webhook 统一为 `/api/webhooks/payment`，兼容 Creem 和 Stripe 签名头；
- 生成 `nextdevtpl.generated.json`，记录模块、适配器、目标和 Binding 需求；
- 生成轻量 smoke test，不复制依赖完整测试数据库的仓库测试集；
- 内容型项目安装后自动运行 `fumadocs-mdx`，lockfile 保证依赖版本可复现。

`prepack` 会从当前仓库自动组装发布快照。快照保留 `.gitignore` 和 lockfile，
不包含本地环境文件、缓存、依赖目录、完整测试集，以及 `next-env.d.ts` 这类由
Next.js 在类型生成或构建时创建的框架产物。
仓库根和包含内容模块的生成项目在 `postinstall` 运行 `fumadocs-mdx`，保证干净
checkout 在类型检查前生成 `.source/`；未选择内容模块时删除该脚本和依赖。
生成阶段会用 YAML 解析器同步 lockfile 根 importer 与裁剪后的 `package.json`，
所以生成项目可以直接执行冻结安装。生成项目不依赖生成器包，可以独立维护。

4.x M0 的截图工具属于仓库自用内容。模板复制白名单不包含 `e2e/`，重写包清单时还会通过
`package-pruning.ts` 移除 `@playwright/test` 和全部 `visual:` 命令，并同步 lockfile。
纯函数测试及真实项目生成测试共同验证这些内容不会进入用户项目；其他仓库专用命令的既有
泄漏仍记在视图契约的现状清单，本次没有扩大修复范围。

4.x M1 已把界面拼接替换为视图组合。recipe 保存模块视图及公开类型入口、皮肤导出入口、
归属源码路径；生成器据此删除未选视图并生成严格类型的 `src/modules/skin-views.ts`。页面的
HTML 与样式保存在皮肤中，生成器只装配导入、数据或控制入口和薄路由。原有无认证、无
dashboard 和无积分组合的简化外壳、首页回退保持行为不变，具体约定见[视图契约](视图契约.md)。

组合逻辑已按职责拆为 `view-composition.ts`、`workspace-composition.ts` 和 `route-pruning.ts`。
前者生成所选视图映射并裁剪皮肤来源；工作区文件仅装配服务端数据、客户端控制入口和薄路由；
路由裁剪保留已选的嵌套页面及仍承接它们的 Next 特殊文件，清理排除页面的普通辅助文件。
不含 dashboard 的设置与工单组合不再被父目录裁剪误删，也不额外补回未选择的控制台首页。
可选徽标分别在原有用户区与弹出菜单中挂载，生成器不输出徽标或侧栏的外观代码。

Cloudflare 组合会输出 OpenNext 配置和所需 Binding，并在请求期间从 Workers
上下文延迟注入 R2、Workers AI、Email、Workflows 和 Rate Limiting。数据库普通查询
使用 Neon HTTP，`db.transaction` 通过请求级 Neon Serverless 连接池完成。未配置的 Binding
会在对应能力被调用时返回明确错误。生成的 Cloudflare 项目同时带有
`pnpm cf:check`、`cf:build` 和 `cf:deploy` 预检链路，部署前只报告缺失的配置名称，
不会输出 Secret 值。数据库入口会导出支付历史使用的 `DatabaseTransaction` 类型，
Workers logger 与根项目保持完整的订阅事件契约。

Cloudflare Rate Limiting 的 `namespace_id` 由 Worker 项目名的 SHA-256 派生值和固定
用途槽位生成，输出为账户要求的正整数。项目名对应的基址和用途槽位均保持稳定，生成
项目移动目录或重新组装模板时不会因为路径变化而更换限流计数器；七个 Binding 在同一
项目内各自使用独立 namespace。

自定义组合未选 Dashboard 时，生成器仍保留认证布局的登录保护，但改用轻量页面壳，
避免导入已经裁剪的 Dashboard 组件。兼容性矩阵会同时检查选中适配器、环境变量、Schema、
路由和未选源码是否符合选择。

## 验证方式

- 在临时目录生成所有官方预设并安装依赖。
- 每个预设运行 lint、typecheck、测试和 build。
- 检查未选模块的文件、依赖、环境变量和数据库表全部缺席。
- Windows、Linux 和 CI 环境使用相同输入生成一致结果。
- 打包后检查 npm tarball 包含 CLI、模板快照和 recipe，不包含本地密钥或缓存。
- 2026-07-23 根门禁：format、lint、typecheck、build 全部通过；完整测试为
  25 个文件、318 个用例全部通过。
- `minimal`、`saas`、`ai-saas` 和一组 SMTP + S3 自定义组合均在独立临时目录
  完成安装、lint、typecheck、smoke test 和 build。
- npm tarball 与打包后 CLI 已验证；敏感或缓存条目计数为 0。
- `pnpm release:check` 会重新组装快照，校验 roadmap 与 npm 版本一致，并检查
  tarball 的 CLI、catalog、模板入口和禁止文件。
- Cloudflare 生成测试会检查 namespace 为正整数、同一项目内不重复、不同项目间不共享，
  以及相同 Worker 项目名在不同目录生成时保持相同 namespace；同时检查数据库事务类型
  和订阅日志事件已写入最终生成结果。
- `db:generate`、`db:generate:init` 和 `db:generate:checked` 会格式化并检查
  `drizzle/meta`，确保迁移生成文件满足 Biome 门禁。
- 2026-07-24 M6 验证发现并修复裁剪后 lockfile 仍声明已删除依赖的问题；
  `minimal-server` 已通过 `pnpm install --frozen-lockfile`。
- 2026-07-24 Linux CI 验证发现模板清单错误依赖被忽略的 `next-env.d.ts`；现已
  从源码清单和发布快照移除，生成器测试覆盖干净 checkout 场景。
- 实现提交：`8c4e71f`（`feat: add composable project generator`）。
