> 模块定位：为独立 SaaS 预置获客、激活、付费、留存和故障事件
>
> 对应代码：`src/features/payment/`、`src/features/credits/`、
> `src/app/api/webhooks/payment/route.ts`、`src/lib/auth/index.ts`、
> `src/lib/telemetry/auth.ts`、`src/lib/telemetry/events.ts`、
> `src/services/telemetry.ts`
>
> 所属里程碑：[M1 - v3.1 标准运营事件与来源归因](../roadmap3.x.md#m1)
>
> 当前状态：进行中
>
> 最近更新时间：2026-08-01

## 职责与边界

本模块负责把通用 SaaS 生命周期接入现有业务完成点，并定义来源归因和身份衔接。
它不猜测产品的核心价值，项目必须明确接入首次价值和持续核心动作。

## 结构与数据流

```text
访问 -> 注册 -> 首次价值 -> 订阅 -> 持续核心动作
  |       |         |          |          |
来源    Auth      产品接入点   支付真相    产品接入点
```

标准事件分为 `acquisition`、`auth`、`activation`、`product`、`billing`、
`usage`、`support` 和 `system`。每个 feature manifest 登记自己拥有的事件，生成器
只保留已选择模块对应的事件定义和接入代码。

## 关键决策

- `first_value.completed` 是默认激活节点，只允许在业务结果成功后发送。
- `core_action.completed` 用于活跃与留存，项目必须记录具体动作类别。
- 注册或登录时将匿名 ID 与内部用户 ID 关联，不上传邮箱和姓名。
- 保存首次来源与最近来源，UTM 值限制长度并过滤敏感参数。
- 支付、订阅和积分事件以服务端结果为准，客户端点击只描述意图。
- 开发、测试、预览和生产环境严格分开，默认运营报表只展示生产数据。

## 当前实现

支付 Checkout、支付 Webhook、订阅状态、订阅积分授予、积分购买 Checkout、积分
消费和积分过期已经通过 `trackServerEvent()` 发布标准服务端事件。取消订阅 Action
发布请求事件，最终状态由 Webhook 发布，避免同一完成结果重复计数。分析适配器未配置
时仍保留无外部请求的 fallback，业务模块不会因埋点服务缺失而无法生成或运行。

Better Auth 的用户、会话和账号创建钩子已经接入 `signup.completed`、
`login.completed` 和 `identity.linked`。注册创建用户时会标记当前请求，避免同一注册
流程创建会话后重复记为登录；OAuth 回调通过匿名 Cookie 保留来源和匿名身份。

`src/lib/telemetry/events.ts` 提供 `trackFirstValueCompleted()` 和
`trackCoreActionCompleted()` 两个明确入口，项目需要在真实业务结果成功后传入动作名称。
任务、API 和 Action 失败事件仍待后续 task 接入。

## 验证方式

- 单元测试每个事件的必填属性、可选属性和禁止属性。
- 测试匿名访问到注册后的身份关联和重复登录。
- 测试支付 Webhook 重放不会重复生成业务完成事件。
- 架构测试检查模块只能发布已登记事件。
- 生成各官方预设，确认未选模块的事件和属性 Schema 被删除；生成 `analytics:none`
  与支付、积分模块的组合，确认 telemetry fallback 和业务导入仍然可用。
- 单元测试覆盖认证路径判定、注册上下文去重、来源/UTM 归因解析和激活事件输入。
