# 收入与订阅健康

> 模块定位：从服务端业务事实计算收入、付费转化和订阅健康指标
>
> 对应代码：`src/features/payment/`、`src/features/subscription/`、
> `src/db/schema/subscription.ts`、`src/features/operations/`
>
> 所属里程碑：[M3 - v3.3 收入与订阅健康](../roadmap3.x.md#m3)
>
> 当前状态：已完成
>
> 最近更新时间：2026-08-02

## 职责与边界

本模块负责建立可审计的支付与订阅读模型，并向运营驾驶舱提供收入指标。它不承担
正式会计记账，也不使用浏览器埋点确认收入。

## 结构与数据流

```text
Creem / Stripe Webhook -> 规范化支付事件 -> 订阅读模型 -> 收入指标
                                      \-> 产品分析事件（用户路径）

价格页 -> 计划变更 Action -> Creem / Stripe
账单页 -> 订阅当前状态 + 订阅历史
```

## 关键决策

- 金额包含货币、最小货币单位和发生时间，禁止使用浮点数保存金额。
- 外部事件 ID 和支付供应商用于幂等与审计。
- MRR 只统计有效经常性订阅，年付按明确规则折算到月。
- 退款、争议、失败、宽限和取消分别建模，不能只依赖当前订阅状态。
- 收入、到账和估算 MRR 在指标名称中明确区分。
- 支付供应商能力不同，由适配器声明可提供的数据和缺口。
- 一个用户只保留一条当前订阅记录；历史变更写入 `subscription_history`。
- 升级立即调用供应商的立即补差价能力，降级先保留当前权益并在下一周期切换。
- 取消默认安排在当前周期结束时执行，周期结束前可以调用恢复接口。
- 订阅 Checkout 使用用户级短期锁和请求 ID；同一价格的有效 Checkout 直接复用。

## 当前实现

`revenue_event` 位于支付 Schema 中，保存供应商、外部事件 ID、事件类型、用户、订阅、
价格、货币、最小货币单位金额、周期和发生时间。`recordRevenueEvent` 使用
`external_event_id + kind` 幂等，并把未配置价格的金额保留为 0，避免把未知值伪装成
已确认收入。

支付 Webhook 已记录 checkout 成功、订阅激活与续费、取消、支付失败和退款。订阅成功
事件使用 `subscriptionId + currentPeriodStart` 作为稳定键，因此 checkout 与 active
重复到达不会重复计入，续费周期变化后会生成新的收入事实。Stripe 已规范化失败支付
与退款事件；Creem 保留相同契约的可选字段。

`subscription` 保存用户当前权益和待生效价格，`subscription_history` 保存创建、升级、
降级、取消、恢复和续费记录，`subscription_checkout` 保存短期 Checkout 锁。数据库同时
对 `subscription.user_id`、Checkout 用户和请求 ID 建立唯一约束。迁移 `0007` 会在建立唯一
约束前按有效状态和最近更新时间保留一条旧订阅记录，避免历史重复数据阻塞升级。

计划变更由 `changeSubscriptionPlan` 校验已登记价格和价格周期。升级使用
`proration-charge-immediately`，降级使用 `proration-none`，Webhook 在下一周期开始时
才把待生效价格写入当前价格。取消和恢复分别调用供应商的 scheduled cancel/resume，删除
账户仍使用 immediate cancel。

运营查询从服务端收入事实聚合周期确认收入、退款、支付失败、周期流失、付费用户与
付费转化率；当前有效订阅按价格配置折算 MRR，月付按原价、年付按年价除以 12。运营
页面显示货币、统计周期、时区和每项数据状态。结果用于运营判断，不代表会计报表。

## 验证方式

- `src/test/operations/revenue.test.ts` 覆盖月付、年付折算、最小货币单位、转化率和空
  数据状态。
- `src/test/adapters/payment.test.ts` 覆盖 Creem checkout、订阅升级、周期末取消、恢复，
  以及 Stripe 订阅项更新和失败支付的统一事件契约。
- `src/test/payment/subscription-change.test.ts` 覆盖升级/降级分类、年付切换和待生效价格
  的周期边界。
- `src/test/payment/subscription.test.ts`、`src/test/payment/webhook.test.ts` 和
  `src/test/subscription/user-plan.test.ts` 覆盖订阅生命周期、Webhook、取消后权益和用户
  当前计划读取。
- `pnpm db:generate:checked` 已确认 `drizzle/0007_moaning_dragon_man.sql` 与 Schema
  快照一致；Webhook 的事件领取表、订阅历史表和收入表共同保证重放数据可审计。
- 收入读模型只依赖 Webhook 与订阅数据库，不读取浏览器 checkout 事件。
