# 收入与订阅健康

> 模块定位：从服务端业务事实计算收入、付费转化和订阅健康指标
>
> 对应代码：计划调整 `src/features/payment/`、`src/features/subscription/`、
> `src/db/schema/subscription.ts`、`src/features/operations/`
>
> 所属里程碑：[M3 - v3.3 收入与订阅健康](../roadmap3.x.md#m3)
>
> 当前状态：已完成
>
> 最近更新时间：2026-08-02

## 职责与边界

本模块负责建立可审计的支付与订阅读模型，并向运营驾驶舱提供收入指标。它不承担
正式会计记账，也不使用浏览器埋点确认收入。

## 结构与数据流

```text
Creem / Stripe Webhook -> 规范化支付事件 -> 订阅读模型 -> 收入指标
                                      \-> 产品分析事件（用户路径）
```

## 关键决策

- 金额包含货币、最小货币单位和发生时间，禁止使用浮点数保存金额。
- 外部事件 ID 和支付供应商用于幂等与审计。
- MRR 只统计有效经常性订阅，年付按明确规则折算到月。
- 退款、争议、失败、宽限和取消分别建模，不能只依赖当前订阅状态。
- 收入、到账和估算 MRR 在指标名称中明确区分。
- 支付供应商能力不同，由适配器声明可提供的数据和缺口。

## 当前实现

`revenue_event` 位于支付 Schema 中，保存供应商、外部事件 ID、事件类型、用户、订阅、
价格、货币、最小货币单位金额、周期和发生时间。`recordRevenueEvent` 使用
`external_event_id + kind` 幂等，并把未配置价格的金额保留为 0，避免把未知值伪装成
已确认收入。

支付 Webhook 已记录 checkout 成功、订阅激活与续费、取消、支付失败和退款。订阅成功
事件使用 `subscriptionId + currentPeriodStart` 作为稳定键，因此 checkout 与 active
重复到达不会重复计入，续费周期变化后会生成新的收入事实。Stripe 已规范化失败支付
与退款事件；Creem 保留相同契约的可选字段。

运营查询从服务端收入事实聚合周期确认收入、退款、支付失败、周期流失、付费用户与
付费转化率；当前有效订阅按价格配置折算 MRR，月付按原价、年付按年价除以 12。运营
页面显示货币、统计周期、时区和每项数据状态。结果用于运营判断，不代表会计报表。

## 验证方式

- `src/test/operations/revenue.test.ts` 覆盖月付、年付折算、最小货币单位、转化率和空
  数据状态。
- `src/test/adapters/payment.test.ts` 覆盖 Creem checkout、Stripe 订阅和 Stripe 失败
  支付的统一事件契约。
- `pnpm db:generate:checked` 已确认 `drizzle/0004_handy_wallflower.sql` 与 Schema
  快照一致；Webhook 的事件领取表和收入表共同保证重放幂等。
- 收入读模型只依赖 Webhook 与订阅数据库，不读取浏览器 checkout 事件。
