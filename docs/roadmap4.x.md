# NextDevTpl 4.x 路线图

> 当前版本：`v3.0.0`
>
> 当前阶段：M0 基线与前置修复（已完成）；下一阶段 M1 视图契约与页面拆分
>
> 上一代路线图：[NextDevTpl 3.x 路线图](roadmap3.x.md)
>
> 最近更新时间：2026-11-06

## 项目目标

NextDevTpl 4.x 让生成项目的界面可以整套替换。皮肤负责长相，从颜色、字体、组件到整页
版式都可以换；登录、支付、积分、数据库等功能由核心提供，所有皮肤共用同一份代码和修复。
同一套皮肤既能生成带完整功能的项目，也能导出只有前端的项目。

## 核心原则

1. 皮肤只改长相，不碰功能。皮肤需要的数据和动作全部通过视图约定从核心获取，不直接访问
   数据库、适配器或服务。
2. 面向用户的页面拆成两半：路由外壳负责会话、取数据和动作，皮肤视图负责全部界面。两半
   之间的约定用严格类型表达，缺视图或用错数据在构建时失败。
3. 价格、套餐、积分数量等业务数据只来自核心配置，皮肤不得写死。
4. 皮肤在生成时确定。生成后的项目不依赖生成器、皮肤来源或任何线上服务。
5. 买家可调的部分集中在少量变量（品牌色、字体、圆角、默认明暗），调整变量不破坏皮肤。
6. 默认皮肤保持 v3.0.0 的外观，拆分前后截图一致；4.x 不顺带改设计。
7. 管理后台、文档站和演示页不做整页换皮，只跟随皮肤的变量层和基础组件。
8. 未选择的皮肤、字体、素材和演示数据不进入生成项目；皮肤自带素材必须写明来源和授权。

## M0 - v4.0 基线与前置修复

为拆分建立可对比的基线：给 17 个面向用户的页面截图，逐页整理数据、动作和状态清单。同时
修复 review 总览中会影响收款的两个问题：改过套餐后续费历史不再记录（P1-028），取消订阅
失败却提示成功（P2-019）。详见[视图契约](模块设计/视图契约.md)。

完成依据：[2026-11-06 验收与提交记录](进度/2026-11-06.md)。

<a id="m1"></a>
## M1 - v4.1 视图契约与页面拆分

营销、登录注册、用户控制台三组共 17 个页面改成“路由外壳 + 皮肤视图”。直接查数据库的页面
改为调用核心取数；登录、注册、设置、工单、购买积分等表单的交互逻辑抽成无界面的共用逻辑。
生成器里按模块拼出的界面代码（精简侧栏、控制台布局、无积分首页）改由视图约定中的可选数据
驱动。详见[视图契约](模块设计/视图契约.md)。

<a id="m2"></a>
## M2 - v4.2 皮肤包与默认皮肤

确定皮肤包的目录、清单和规矩检查，把现有界面整理成默认皮肤，开放品牌色、字体、圆角、
默认明暗等可调变量。用一套刻意不同的测试皮肤替换全部视图，证明约定完整。详见
[皮肤系统](模块设计/皮肤系统.md)。

<a id="m3"></a>
## M3 - v4.3 生成器选择皮肤

生成项目时可以选择内置皮肤、本地目录或远端皮肤包。远端包支持携带授权凭证下载并校验完整性；
凭证只从环境变量读取，不写入生成结果。详见[皮肤系统](模块设计/皮肤系统.md)和
[项目生成器](模块设计/项目生成器.md)。

<a id="m4"></a>
## M4 - v4.4 StyleKit 免费配色

仓库保存 StyleKit 公开配色的快照，生成时按名称套用到默认皮肤，自动补齐成功、警告和背景
氛围等缺失颜色，并检查文字对比度。详见[皮肤系统](模块设计/皮肤系统.md)。

<a id="m5"></a>
## M5 - v4.5 纯前端导出

同一套皮肤导出为不含后端的项目：视图使用演示数据，动作改为演示反馈，数据库、登录、支付
等模块与环境变量全部裁剪。详见[纯前端导出](模块设计/纯前端导出.md)。

<a id="m6"></a>
## M6 - 4.x 皮肤制作文档与发布

补齐中英文皮肤制作指南（视图约定、目录与清单、规矩检查、可调变量、验收清单、素材授权与
去品牌检查）、生成器参数说明和 3.x 升级说明，发布 v4.0.0。详见
[皮肤系统](模块设计/皮肤系统.md)。

## 完成定义

里程碑只有同时满足以下条件才可标记为“已完成”：

1. 模块文档反映实际代码、约定和限制。
2. 核心逻辑有单元测试（视图约定、页面取数、表单逻辑、规矩检查、皮肤解析、配色派生、
   对比度计算等），纯展示层不写单测。
3. 格式化、lint、严格类型检查、相关测试和生产构建全部通过。
4. 涉及界面的里程碑附明暗 × 电脑/手机截图验收；默认皮肤与 M0 基线一致。
5. 代码和文档以独立 commit 提交并推送，路线图记录对应证据。

## 暂缓范围

- 管理后台、文档站和演示页的整页换皮。
- 邮件模板跟随皮肤。
- 生成后的项目内置皮肤切换。
- 皮肤商店、在线授权和收费服务；生成器只提供通用的远端下载与完整性校验。
- 可视化皮肤编辑器。
- 自动把 3.x 生成的项目迁移到新结构；沿用升级指南的“重新生成对照项目、审查差异、分批合并”。

## 关键决策

| 日期 | 决策 | 原因 |
|---|---|---|
| 2026-10-19 | 4.x 主线为皮肤系统 | 同一套 SaaS 功能需要多种完整外观；每种外观复制一份模板会让修复和升级成倍增加 |
| 2026-10-19 | 皮肤只改长相，功能由核心提供 | 深度皮肤可以整页重写，同时所有皮肤共享同一份登录、支付、积分和数据库代码 |
| 2026-10-19 | 管理后台、文档站、演示页不做整页换皮 | 最终用户主要接触营销、登录和控制台页面，先保证这些页面可以整页替换 |
| 2026-10-19 | 皮肤在生成时确定，生成结果独立 | 延续 2.x 以来生成项目不依赖生成器与线上服务的原则 |
| 2026-10-19 | 默认皮肤保持 v3.0.0 外观 | 拆分属于结构调整，用截图基线证明没有顺带改设计 |
| 2026-10-19 | StyleKit 配色以快照形式保存在仓库 | 生成结果可重复、离线可用；StyleKit 为 MIT 许可，生成项目保留署名 |
| 2026-10-19 | 同一套皮肤支持完整项目与纯前端两种导出 | 一次制作，两种交付外观一致 |
